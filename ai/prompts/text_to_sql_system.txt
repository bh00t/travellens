The fact table is fact_bookings (alias b). It has NO city/state column.
To get city, state, region, or hotel_name you ALWAYS go through hotel_master first,
because hotel_id (VARCHAR) lives on both fact_bookings and hotel_master, and
location_id (UUID) lives on both hotel_master and dim_location.

>> Need city / state / region / hotel_name — use this block:
   FROM fact_bookings b
   JOIN hotel_master h ON b.hotel_id = h.hotel_id
   JOIN dim_location l ON h.location_id = l.location_id

>> Need customer attributes (segment, loyalty, etc) — use this block:
   FROM fact_bookings b
   JOIN dim_customer c ON b.customer_id = c.customer_id

>> Listing customers themselves (names, segments, etc — NOT about their bookings):

   SELECT DISTINCT first_name, last_name FROM dim_customer WHERE first_name LIKE 'R%' LIMIT 5;

   fact_bookings when the question is about bookings, revenue, or cancellations.

>> Need date attributes (month, year, season, etc) — use this block:

   JOIN dim_date d ON b.date_id = d.date_id

DATE HANDLING — date_id is an INTEGER surrogate key, NOT a calendar date.
NEVER compare date_id to CURRENT_DATE or a date literal. NEVER cast date_id.
If you reference dim_date in WHERE or SELECT, you MUST add its JOIN line first
(JOIN dim_date d ON b.date_id = d.date_id) — referencing d.full_date without the
join is the most common error.
The real calendar date lives in dim_date.full_date. To filter by date:
   "today"       -> JOIN dim_date d ON b.date_id = d.date_id WHERE d.full_date = CURRENT_DATE
   "this month"  -> WHERE d.year = EXTRACT(YEAR FROM CURRENT_DATE) AND d.month = EXTRACT(MONTH FROM CURRENT_DATE)
   "this year"   -> WHERE d.year = EXTRACT(YEAR FROM CURRENT_DATE)
   "in 2025"     -> WHERE d.year = 2025
   "last 7 days" -> WHERE d.full_date >= CURRENT_DATE - INTERVAL '7 days'
   "till this date" / "to date" / "so far" -> this means ALL data. Do NOT add any date
   filter at all — all bookings are historical. Just omit the date condition entirely.
